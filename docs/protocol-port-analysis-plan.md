# 协议/端口分析方案设想

> 状态：规划中（硬件未到位）。本文记录 2026-07 讨论得出的方案结论，配套拓扑图见 [network-topology.html](network-topology.html)。

## 背景与目标

现有监控体系（mi-router-exporter → Prometheus → Grafana）只能拿到小米路由器 API 暴露的**设备级字节数**（累计流量、实时速率），无法按协议/端口维度拆分流量。目标是在不刷机、不破坏小米 Mesh 的前提下，实现全网的协议/端口级流量分析，并接入现有 Prometheus + Grafana 体系。

## 已排除的路线

### 1. 小米路由器原生 API

已实测探测（RA80 / AX3000，原厂固件）：

| 接口 | 结果 |
| --- | --- |
| `misystem/status`、`misystem/devicelist` | 仅设备级字节数（现有 exporter 已用） |
| `misystem/qos_info` | 仅每设备限速配置，QoS 关闭状态，无协议/端口维度 |
| `xqdatacenter/request` | HTTP 500，不可用 |
| `misystem/bandwidth_test` | HTTP 502，不可用 |
| `misystem/active_game` | HTTP 404，不可用 |

结论：原厂固件不暴露 DPI / 连接跟踪数据，此路不通。

### 2. 刷 OpenWrt

RA80 仅有社区固件支持（不在 OpenWrt 官方硬件表内）。代价过大，放弃：

- 社区固件无 NSS 硬件加速，2000M 宽带跑不满；部分用户报告 5GHz 覆盖变差
- 小米私有 Mesh 协议丢失，三台设备需全刷并自建 802.11s/WDS，漫游体验下降
- 失去米家 App 管理等原生功能，且刷机有变砖风险

### 3. 仅分析 Mac mini 本机流量

零硬件成本，但只覆盖单机，作为备选起步方案保留，不是最终目标。

## 选定方案：镜像交换机 + 独立采集盒

### 前提条件（已满足）

- 三台 AX3000 Mesh 为**有线回程**（装修时预埋）
- 主路由 **Wi-Fi 关闭**，仅做网关——因此不存在"主路由直连 Wi-Fi 设备"盲区，全网流量都会经过镜像点

### 拓扑

在主路由与两台子节点之间串入一台带端口镜像的网管交换机，采集盒挂镜像口。**现有连线一根不动**，仅新增设备与插拔回程线（断网几十秒）：

1. 两台子节点的回程网线从主路由 LAN 口挪到交换机普通口
2. 交换机上联口接回主路由 LAN 口
3. 采集盒接交换机镜像目标口
4. 镜像配置：将**上联口双向流量**复制到镜像口（所有南北向流量都经过上联口，镜像一个口即覆盖全网）

详细图示：[network-topology.html](network-topology.html)（灰色=现有连线，绿色=新增连线，橙色虚线=镜像流量）。

### 覆盖范围

| 流量类型 | 是否可见 |
| --- | --- |
| 子节点下所有设备（无线+有线）的上网流量 | ✅ |
| 跨节点的设备互传 | ✅ |
| 同一子节点内两设备互传（如手机投屏电视） | ❌ 不出节点 |

镜像点在 NAT 之前的 LAN 侧，保留每台设备的内网 IP/MAC，可按设备归因。光猫位于主路由 WAN 侧，不影响分析。

### 硬件清单

| 设备 | 建议 | 参考价 |
| --- | --- | --- |
| 网管交换机（带端口镜像） | 千兆入门款如 TL-SG105E；在意 2000M 跑满时镜像丢样本可上 2.5G 网管款 | ¥80–200 |
| 采集盒 | 树莓派 4/5、二手 N100 迷你主机等。**建议双网口**：一口收镜像、一口正常联网供 Prometheus 抓取 | ¥100–400 |

镜像口溢出/丢包只影响分析采样，不影响正常上网；整套方案随时可拆除回退。

### 软件架构

```text
镜像流量 → 采集盒（libpcap 抓包，按 设备MAC/IP + 协议 + 端口 聚合为计数器）
        → /metrics 端点 → 现有 Prometheus 新增 scrape 目标 → Grafana 协议/端口看板
```

- 采集器作为本仓库新模块（与 `mi-router-exporter` 并列）
- 备选：直接跑 ntopng（开箱即用 Web 界面），但与现有 Grafana 体系割裂
- 分析能力：端口/协议/目标 IP/每设备排行；TLS 加密流量可通过 SNI 识别到应用级别（如 YouTube、微信）

### 为什么不镜像 WAN 口

光猫与主路由之间抓包虽然"全看到"，但已经过 NAT，所有流量源地址均为路由器自身，**无法按设备归因**，故镜像点必须在 LAN 侧。

### 关于 Mac mini 作为采集机的讨论（已否决）

Mac mini 经 Mesh 无线上网，镜像原始帧无法穿越无线网络送达。曾考虑用其房间墙线接镜像口、该房间节点改无线回程，但会引入降速与潜在盲区（节点若无线挂到主路由则绕过交换机）。最终选择独立采集盒，Mac mini 与现网均不变动。
